## Muon: requirements
- Implement in a new file `method/vla/muon.py` (credit: Keller Jordan's Muon, and the Moonlight paper's update-RMS matching). Use the standard quintic Newton–Schulz orthogonalisation (5 iterations, coefficients (3.4445, -4.7750, 2.0315)), computed in bf16 on CUDA / fp32 on CPU, applied to the **Nesterov momentum** (momentum 0.95). Handle non-square matrices by transposing so rows <= cols.
- **Update scale: Moonlight RMS matching**: scale the orthogonalised update by `0.2 * sqrt(max(rows, cols))` so that Muon can share the AdamW learning rate and weight-decay schedule (state this in the README). Decoupled weight decay applied to Muon params too (`p *= 1 - lr * wd`).
- **Parameter split (hybrid):** Muon only for 2-D weight matrices *inside* transformer blocks of the ViT, the prefix transformer and the action expert (attention q/k/v/out projections, MLP up/down). For PyTorch `nn.TransformerEncoderLayer`/`MultiheadAttention` fused `in_proj_weight` (3d×d), orthogonalise **q, k and v separately** (split into 3 row blocks). Everything else uses AdamW: patch-embedding conv, positional embeddings, token/state/time embeddings, input/output projections and heads (including the distillation head and the action output projection), all norms, all biases, adaRMSNorm modulation layers (state your choice for modulation and justify it in one line). Print a table at start: parameter count per optimizer and per group.
- Config fields: `optimizer: adamw|muon` (default `adamw`, so existing behaviour and checkpoints are unchanged), `muon_momentum: 0.95`, `muon_ns_steps: 5`. With `optimizer: muon`, `lr` is the shared lr (Moonlight matching) unless `muon_lr` is given explicitly; keep the existing warmup + cosine schedule for both groups. Resume must restore Muon state (momentum buffers) and refuse a resume with a different optimizer.
- Unit tests (CPU, fast) in `method/vla/test_muon.py`: Newton–Schulz output has singular values in roughly [0.6, 1.2] for random square and rectangular matrices; RMS of the scaled update ≈ 0.2 × typical AdamW update RMS (state what you measure); fused in_proj split gives the same result as orthogonalising q/k/v separately; params assigned to exactly one group, none missing; a 30-step tiny overfit on fake data decreases loss with Muon at least as fast as AdamW at its default lr (report both curves).
